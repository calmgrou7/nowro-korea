# NOWRO 고정 주소 배포 — 2026-10-08

## 현재 상태

사용자가 메일 인증 완료를 알려주었고, 공개 미리보기 DB에서 회원 인증 연결 1건과 저장된 인증 세션 1건을 확인했다. 다른 기기 기록 복원은 별도 확인한다. 현재 공개 주소는 임시 Cloudflare 터널이며 고정 배포를 완료하지 않았다.

배포 전 공개 DB를 `.data/backups/pre-deploy/nowro-ccEZiQ`에 백업했다. 무결성·외래키·체크섬·테이블 건수 검증 및 `.data/recovery-test/pre-deploy-20261008/nowro.sqlite`로 새 파일 복구를 통과했다. 이후 사용 중 발생한 변경은 배포 직전 새 백업으로 반영해야 한다. 백업은 공개 소스 ZIP에 포함하지 않는다.

Render 대시보드 접속은 로그인 화면으로 이동했다. 배포 계정 로그인, NOWRO 전용 저장소 연결, 실제 요금 확인 및 서비스 생성은 아직 수행하지 않았다.

현재 앱은 Node 24 서버와 SQLite를 사용한다. 정적 페이지 배포만으로는 로그인, 상점 등록, 스탬프와 보상 저장이 작동하지 않는다. Render의 영구 디스크 구성으로 먼저 단일 서버를 운영할 수 있다. 유료 서비스 생성은 계정 소유자가 가격을 확인하고 승인해야 한다.

## 준비한 구성

- `render.yaml`: Node 서버, 빌드, 상태 확인, 운영자 미리보기 차단, 1GB 영구 디스크.
- 서버 데이터 경로: `/var/data/nowro`. 이 경로 밖의 파일은 재배포 시 유지되지 않는다.
- `PUBLIC_APP_URL` 입력 항목을 추가했다. Supabase Auth의 Site URL과 정확히 같은 HTTPS 주소를 넣는다.
- `npm run deploy:check -- https://서비스주소`: 인증 설정, HTTPS, 앱 빌드와 운영자 테스트 차단을 확인한다. 실제 로그인이나 이메일 수신을 대신하지 않는다.

## 계정 준비 후 진행

1. NOWRO 전용 Git 저장소에 소스만 등록한다. `.env`, `.data`, 백업, 배송 정보, 인증 토큰, `node_modules`는 등록하지 않는다. 상위 앱개발 폴더 전체를 업로드하지 않는다.
2. Render에서 저장소의 `render.yaml`을 Blueprint로 선택한다. Starter 서버와 1GB 디스크의 실제 가격을 확인한다. 결제와 서비스 생성은 사용자 승인이 필요하다.
3. Supabase URL과 publishable key를 Render 환경변수에 입력한다. 서비스 역할 키나 DB 비밀번호는 이 구성에 필요 없다.
4. Render가 부여한 `https://…onrender.com/` 주소를 `PUBLIC_APP_URL`에 넣고 재배포한다. Supabase Authentication → URL Configuration → Site URL도 같은 주소로 변경한다. 임시 주소를 그대로 두지 않는다.
5. 배포 확인 명령을 실행한다. 모바일에서 새 메일 로그인, 계정 확인, 저장 코스와 스탬프 유지, 로그아웃을 확인한다. 테스트 기록 저장 후 서버를 재시작하고 같은 계정으로 다시 확인한다.
6. 기존 PC의 기록을 옮길 경우 먼저 온라인 백업을 생성하고 검증한다. 새 서버 DB가 비어 있을 때만 별도 이관 계획에 따라 복구한다. 기존 파일을 무조건 덮어쓰거나 실행 중인 SQLite 파일을 복사하지 않는다.

배포는 새 DB로 시작한다. Supabase 인증 계정은 동일하지만 PC에 저장된 코스·스탬프·보상은 자동 이전되지 않는다. 새 서버에서 회원이 재로그인해도 기존 앱 기록 복원을 보장하지 않으므로, 실제 회원 기록을 유지할 경우 백업 이관을 배포 전 확정한다.

## 다음 단계

현재 구성은 단일 서버 MVP용이다. 운영 DB와 이미지 저장소의 Supabase 전환, 실제 상점 승인, 실결제·배송, 회원 탈퇴와 개인정보 정책은 아직 남아 있다. 고정 배포를 정식 서비스 출시 완료로 표시하지 않는다.
