# NOWRO Korea UX 재정의

작성: 2026-10-05

## 제품 UX 목표

사용자는 첫 화면에서 장소를 찾거나 코스를 만들 수 있어야 한다. 찾기 → 비교 → 상세 확인 → 길찾기/저장이라는 흐름을 기준으로 설계한다. 국내 여행자와 영어 사용자에게 같은 기능과 정보의 우선순위를 제공한다.

이번 점검은 현재 구현 화면, 코드, 모바일/PC 브라우저 검증을 바탕으로 한 전문가 검토다. 실제 고객의 사용성 테스트나 전환율 측정을 대체하지 않는다.

## 고객별 핵심 과업

| 고객 상황              | 첫 행동                           | 확인할 정보                                | 완료 행동               |
| ---------------------- | --------------------------------- | ------------------------------------------ | ----------------------- |
| 모바일, 부산 현지      | 카페·식당·체험·바다 바로가기      | 지역, 사진, 예상 비용, 체류시간, 검증 상태 | 상세 → 길찾기           |
| 모바일, 남는 시간 활용 | 코스 만들기 바로가기              | 현재 지역, 가용 시간, 1인 예산, 관심사     | 코스 확인 → 저장        |
| PC, 여행 전 조사       | 지역명/장소명 검색 또는 지역 선택 | 여러 카드의 비용·시간·사진 비교            | 상세 확인, 코스 계획    |
| 영어 사용자            | 영어 기본 화면의 Search/Explore   | 지역 영문명, 한국어 주소, KRW, 검증 상태   | 주소 복사/길찾기        |
| 국내 사용자            | 한국어 전환 → 탐색                | 한국어 명칭, 지역, 비용, 체류시간          | 동일한 길찾기/저장 기능 |

현재 저장은 브라우저 세션 기반이다. PC와 휴대폰 사이의 계정 동기화를 제공한다고 안내하지 않는다.

## 정보 구조

| 메뉴   | EN      | 목적                                            |
| ------ | ------- | ----------------------------------------------- |
| 홈     | Home    | 빠른 검색, 카테고리 진입, 코스 계획             |
| 탐색   | Explore | 부산 전체/지역별 검색, 카테고리 필터, 목록·지도 |
| 저장   | Saved   | 저장한 코스 확인                                |
| 혜택   | Offers  | 쿠폰과 혜택 확인                                |
| 스탬프 | Stamps  | 스탬프 수집 확인                                |

모바일은 하단 메뉴, PC는 상단 메뉴를 계속 노출한다. 선택된 메뉴를 표시하고, 메뉴를 전환하면 해당 화면 위에서 시작한다. 내부 NOW/MAP/TRIP/PASS/PASSPORT 식별자는 유지하되 고객에게는 기능 이름을 보여준다.

## 점검 결과와 반영

| 문제                                | 영향                                  | 반영한 개선                                                       |
| ----------------------------------- | ------------------------------------- | ----------------------------------------------------------------- |
| 큰 소개 영역 이후에 탐색이 등장     | 빠른 정보 탐색을 위해 여러 번 스크롤  | 홈 최상단에 검색, 4개 카테고리 바로가기, 코스 만들기 이동         |
| MAP과 PASSPORT 등 메뉴 역할 불명확  | 초기 사용자의 탐색 비용 증가          | 홈·탐색·저장·혜택·스탬프, 5개 언어 기능명                         |
| 검색이 코스 선택 지역에 제한        | 다른 지역 장소를 검색해도 나오지 않음 | 검색 범위는 부산 전체 기본, 별도 지역 필터                        |
| 검색과 추천 지역 설정이 공유됨      | 탐색 중 코스 출발점까지 바뀜          | 검색 지역 상태와 코스 위치 상태 분리                              |
| 검색이 장소명만 확인                | 지역명으로 찾기 어려움                | 5개 언어 장소명·지역명, 주소·카테고리 검색, 공백 분리어 모두 일치 |
| 결과가 없을 때 빈 목록만 제공       | 다음 행동을 알기 어려움               | 결과 수·현재 범위·카테고리, 빈 결과 안내, 검색 초기화             |
| 일부 모바일 텍스트·조작 영역이 작음 | 판독과 터치 어려움                    | 입력 16px, 카드 제목 16px, 핵심 모바일 버튼 최소 높이 44px        |
| 상세를 스크롤하면 닫기 버튼을 놓침  | 상세 화면에서 나가기 어려움           | 모바일 상세 제목·닫기 영역 고정                                   |

검색은 로컬 카탈로그의 문자열 검색이며 오타 교정/의미 검색은 지원하지 않는다. 다국어 키워드가 모든 업체명과 동의어를 이해한다고 주장하지 않는다.

## 화면별 UX 기준

### 홈

1. 첫 화면에서 검색 입력과 카테고리 선택에 접근한다.
2. 코스 만들기 링크는 코스 입력 영역으로 직접 이동한다.
3. 모바일 소개는 짧게, 사진은 압축된 높이로 유지한다.
4. 사용자가 과업을 시작하기 전에 로그인·GPS 허용을 요구하지 않는다. 위치 허용은 선택이며 지역 선택으로 대체한다.

### 탐색

1. 기본 목록은 부산 전체. 검색어와 지역, 카테고리는 함께 적용한다.
2. 목록/지도 전환 시 검색 조건을 유지한다.
3. 결과 수와 범위를 표시하여 조건이 왜 좁아졌는지 알 수 있게 한다.
4. 결과 없음에는 다른 검색어/지역 안내와 초기화 행동을 제공한다.
5. 카드에는 이름, 지역, 사진, 예상 체류시간, 예상 1인 비용, 샘플 여부를 일관되게 배치한다.
6. 검증된 영업정보가 없으면 '영업중', 현재 대기시간, 실제 이동거리 등의 배지를 만들지 않는다.

### 코스 계획

기본 정보는 지역 → 시간 → 예산 → 관심사. 동행자·이동수단·접근성·식이·복귀 조건은 기존 펼침 영역에서 제공한다. 예산과 시간은 추천에 실제 영향을 주므로 기본값을 숨기지 않는다. 추천 결과는 추정 시간/비용과 샘플 상태를 함께 표시한다.

### 상세

사진 → 명칭 → 핵심 설명 → 주소/비용/시간 → 운영·검증 정보 → 길찾기 순서로 확인한다. 외국인에게 한국어 주소 복사와 외부 지도 접근을 제공한다. AI 사진은 업체 실사진으로 오인하지 않게 표시한다.

### PC

동일한 검색 기능과 조건을 사용한다. 넓은 화면에서는 카드 4열, 코스 비교와 입력 영역의 다열 배치를 유지한다. 모바일 하단 메뉴 대신 상단에 동일한 기능명을 노출한다.

## 품질 기준과 다음 검증

- 핵심 모바일 터치 영역 목표: 높이 44px 이상. 이는 제품 설계 목표다. WCAG 2.2 AA 2.5.8의 최소 기준은 예외 조건을 포함한 24×24 CSS px이므로 44px을 AA 요구사항이라고 주장하지 않는다.
- 모바일 입력 16px, 본문 주요 정보 14–16px 권장. 버튼·검증 배지 등 보조 정보는 시각 검증을 병행한다.
- 320px에서 페이지 가로 스크롤 없이 검색과 하단 탐색을 사용한다.
- 새로 발생한 핵심 상태는 접근성 상태 메시지로 결과 수를 알린다.
- 기능 이름은 언어별 번역, 통화는 KRW, 한국어 주소는 그대로 제공한다.
- 키보드 초점 표시와 기존 상세 초점 관리, 모션 축소 설정을 유지한다.

사용성 검증 목표(아직 고객 측정 결과 아님): 한국어 사용자와 영어 사용자 각각 5명에게 '카페 찾기', '다른 지역 검색', '예산 내 코스 만들기', '길찾기' 과제를 주고, 첫 행동까지 시간·완료율·되돌아가기 횟수·필터 실수·샘플 오인 여부를 측정한다. 카테고리 목록까지 1회 조작, 상세까지 2회 조작을 현재 진입 흐름의 기준으로 삼는다.

다음 우선순위: 실제 업체와 가격·운영시간 검증, 실제 예약/혜택 적용 가능 여부 안내, 동의 기반으로 수집 가능한 최소 UX 지표 설계. 실제 측정 없이 전환율·속도 개선 수치를 제시하지 않는다.

## 확인 기록

- 320px 모바일: 검색/하단 탐색 표시, 페이지 너비 초과 없음, 카테고리 버튼 74px·관심사 버튼 44px·하단 버튼 69px 확인.
- 카페 바로가기: 부산 4개 지역의 카페 4개 표시.
- 없는 검색어: 0개 안내와 초기화 표시. 초기화 후 부산 전체 16개 복구.
- 한국어 '전포': 카페 1개 표시.
- 코스 만들기: 입력 영역이 화면 상단 20px 위치로 이동.
- PC 1280px: 상단 메뉴, 전체 검색, 4열 카드 목록 확인.
- 고객 인터뷰, 실제 기기 OS별 검증, 정식 접근성 감사는 수행하지 않음.
