# NOWRO Korea 1차 개발 보고서

작성일: 2026-10-05 (한국 시간)

현재 결과는 **실행·검증된 로컬 개발판**입니다. 기획서의 현장 사용 가능한 MVP 전체 완료 기준을 충족했다고 보고하지 않습니다. 비회원 추천 → 장소 교체 → 저장 → 쿠폰 발급 → 사업자 확인 → 현장 코드 스탬프의 개발 흐름을 실제 서버 처리로 확인했습니다.

## 저장소 확인과 작업 범위

- 기존 작업 폴더에는 여러 다른 서비스가 있었고 NOWRO 프로젝트는 없었습니다.
- 상위·현재 폴더와 프로젝트 경로에서 적용할 AGENTS.md를 찾지 못했습니다.
- 기존 프로젝트와 사용자 파일을 보존하고 `nowro-korea/`에 새 프로젝트를 만들었습니다.
- 원문 기획서는 [SPEC.md](SPEC.md)에 보존했습니다.
- React + TypeScript + Vite, 모바일 우선 UI, Node 24 HTTP API를 구성했습니다.
- 키 없이도 서버 검증을 실행하도록 로컬 SQLite를 사용했습니다. Supabase로 연결한 것처럼 표시하지 않습니다.
- package-lock과 고정 패키지 버전을 생성했습니다. Git에는 새 프로젝트 파일이 미추적 상태이며, 자동 커밋·푸시·배포는 하지 않았습니다.

## 실행·확인

```powershell
cd "C:\Users\calmg\OneDrive\문서\앱개발\nowro-korea"
npm ci
npm run dev
```

http://127.0.0.1:5173 에서 이용합니다. 개발 API는 8787 포트입니다. 현재 개발 서버를 실행해 두었습니다.

확인 순서:

1. 언어 선택 후 권역·시간·예산·취향 입력. 출발 시각을 한국 시간으로 수정할 수 있습니다.
2. 코스 생성·비교 → 코스 상세 → 장소 교체·삭제·순서 이동. 불가능한 변경은 이전 코스를 유지합니다.
3. 코스 저장 → TRIP에서 확인.
4. PASS에서 샘플 쿠폰 발급 후 코드 복사.
5. 설정 → 로컬 Partner 테스트 계정 → 쿠폰 코드·결제금액으로 사용 확인.
6. Partner에서 서명 QR·대체 코드 생성 → Traveler로 돌아와 PASSPORT에 코드 입력.
7. 가격·체류시간 수정 요청 → Administrator에서 승인·반려 → 공개 카탈로그 반영 확인.

로컬 테스트 계정은 실제 로그인·업체 인증이 아닙니다. `npm start`에서는 기본 비활성화되며 공개 바인딩도 차단합니다. QR의 localhost 링크는 다른 기기에서 사용할 수 없으므로 대체 코드로 로컬 확인합니다.

## 검증 결과

### 실행 검증

- `npm run build`: TypeScript 검사와 Vite production build 성공.
- `npm test`: **27개 테스트, 27개 통과, 실패 0**. PostgreSQL 상위 테스트와 7개 하위 검증을 포함한 Node 테스트 출력 기준입니다.
- Playwright / 설치된 Chrome: **12개 브라우저 확인 항목 통과, 페이지 런타임 오류 0**.
- 데스크톱 1440px 및 모바일 390px 화면을 이미지로 저장해 직접 확인했습니다. 모바일 가로 넘침 없음.

### 코스·서버

- 2시간·4시간·반나절·하루 모두 이동+체류+대기+복귀+완충 ≤ 가용시간, 상한비용 ≤ 예산 검사.
- 미등록·중복 장소 ID 거부, 0원 예산에 유료 장소 배제.
- 도착 영업·최종 입장·체류 종료, 복귀 마감, 예약 미확인, 식이·접근성·어린이 확인 필터 검사.
- 장소 교체로 총비용·종료시각이 재계산되고 불가능한 변경은 거부.
- 사용자 A/B 코스 조회·삭제 차단.
- 발급 상한 30개와 세션당 1개, 사업자 소유권·최소금액·중복사용·쿠폰 중지 검사.
- QR 변조·재사용·중복 장소·만료/증빙 불일치와 발급 권한 검사.
- 승인 전 공개정보 유지, 타 업체 수정·사업자 자체 승인 차단.
- 동의 없는 분석 이벤트 제외, 분석 동의 철회 시 이벤트 삭제, 만료 게스트 정리.
- HTTP 쿠키 소유권·CSRF·운영자 미리보기 비활성화 검사.

### PostgreSQL 준비 스키마

PGlite의 실제 PostgreSQL 실행환경에 Supabase 역할과 `auth.uid()`를 모사해 검증했습니다.

- 모든 public 테이블의 RLS 활성화.
- 비회원 공개 장소 열람과 쿠폰 RPC 차단.
- 사용자 소유권·소유자 재할당 차단.
- 직접 쿠폰 발급 쓰기 차단과 RPC 중복·수량 제한.
- 업체 소유권·최소금액·사용 1회 제한, 업체의 여행자 코스/발급내역 열람 차단.
- 현장 nonce 발급 권한·재사용 방지, 증빙 테이블 직접 접근 차단.
- 사업자 수정 요청 자체 승인·직접 장소 공개 변경 차단.

이는 실제 Supabase Auth·REST·Edge Functions·동시 부하·Security Advisors 검증을 대체하지 않습니다. 원격 프로젝트에 SQL을 적용하지 않았습니다.

## 실제 연결과 배포 상태

- 실제 실행: localhost Node HTTP API + SQLite.
- 지도: 외부 OpenStreetMap 개발용 타일 URL, 외부 Google Maps 길찾기 URL.
- Supabase: 미연결. 스키마와 로컬 실행 테스트 준비.
- OpenAI: 미연결. 키·모델 없이 미연결 안내와 규칙형 추천 제공. 실제 유료 호출 없음.
- 장소·혜택: 모두 샘플. 실제 업체 확보·현장 이용 가능으로 표시하지 않음.
- 시각자료: NOWRO용 직접 제작 SVG 일러스트·벡터 아이콘. 실제 장소사진으로 표시하지 않음.
- 공개 웹 배포·도메인·실서비스 운영: 미수행.

5. 실계정 Partner/Admin·사진/영업시간/번역·쿠폰 생성·미션 운영·QR Edge Functions 연결.
