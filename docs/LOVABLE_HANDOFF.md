# NOWRO Lovable 디자인 왕복 작업 — 2026-10-17

사용자 요청: 기존 NOWRO를 Lovable에서 디자인 편집한 뒤 원래 프로젝트로 UI 변경을 가져온다. 원본 백엔드·로그인·결제·회원 데이터 이전이나 정식 배포를 요청한 작업이 아니다.

## 현재 결과

- 연결된 Lovable 계정의 소유자 워크스페이스를 확인했다. 기존 NOWRO 프로젝트 검색 결과는 없었다.
- `node scripts/prepare-lovable.mjs`로 기존 src/shared/public을 복사한 독립 디자인 사본을 생성했다.
- 사본 경로: `.data/lovable-handoff/nowro-1792248761323`.
- 업로드 ZIP: `.data/lovable-handoff/NOWRO-design-handoff.zip` (약 2.9MB). 파일 전송 HTTP 200 성공.
- 사본 빌드 통과. 원본 앱의 `src/api.ts`와 서버는 변경하지 않았다.
- Lovable 프로젝트 생성 요청은 **워크스페이스 크레딧 소진**으로 거절되었다. 프로젝트 ID나 편집 URL을 받지 못했으며, 편집 프로젝트 생성 완료로 안내하면 안 된다. 요금제 변경이나 크레딧 구매는 실행하지 않았다.

## 사본 구성

실제 src 컴포넌트·스타일·번역·로고·부산 사진과 공개 샘플 카탈로그를 포함한다. 사본의 api.ts만 메모리 내 디자인용 어댑터로 대체하여 별도 서버 없이 화면을 편집하게 했다. 실제 인증·결제·스탬프·배송 요청은 처리하지 않는다. 서비스 워커 등록도 사본에서만 제외했다.

`.env`, `.data`, `.git`, 서버, DB, 배송 정보, 인증 토큰, 서명키, node_modules 및 빌드 출력은 ZIP에서 제외했다. 사본의 DESIGN_HANDOFF.md에는 화면·브랜드·기능 보존 지침이 있으며 HANDOFF_BASELINE.json은 원본 파일의 SHA-256 기준 목록이다.

## 크레딧 준비 후 재개

1. 기존 NOWRO Lovable 프로젝트가 생겼는지 다시 검색해 중복 생성을 피한다.
2. 소스가 바뀌었다면 준비 스크립트를 다시 실행하고 새 사본을 빌드한다. 기존 원본 파일을 덮어쓰지 않는다.
3. 업로드 URL은 임시이므로 새 URL을 발급받아 ZIP을 재전송한 뒤 연결된 Lovable 도구로 프로젝트를 생성한다.
4. 초기 요청에는 기존 화면을 그대로 읽어 편집 가능하게 만들고, 디자인 요청 전 대규모 재디자인을 하지 말라고 명시한다. Cloud·회원·결제 연결 및 공개 배포는 하지 않는다.
5. 생성된 ID와 편집 URL을 이 문서에 기록하고, 미리보기의 홈·탐색·저장·혜택·스탬프 및 전문가 폼을 검증한다.

## 디자인 편집 후 원본으로 가져오기

사용자가 Lovable 편집을 완료하면 해당 프로젝트 URL을 이 대화에 전달한다. 연결된 Lovable의 파일 읽기/변경 비교 도구로 코드를 받아 별도 경로에 보관하고 기준 목록과 대조한다. GitHub 신규 권한 부여 없이도 파일을 읽는 경로를 우선 사용할 수 있다. 지속적인 Git sync가 필요하면 그때 계정과 저장소 연결을 별도로 확인한다.

원본에 적용할 것은 검토한 UI/CSS/정적 자산 변경이다. 사본의 api.ts·main.tsx·package/lockfile·vite.config.ts와 디자인용 배너를 원본에 자동 덮어쓰지 않는다. 인증·서버 권한·결제 QR·보상 중복 검증·배송정보 처리를 유지하고, 원본에서 빌드·기존 테스트·모바일 UI 검수를 마친다.
