# 미니 구조 통합 사전 검토

검토일: 2026-11-18. 본 앱 기준 커밋: `17ad8c8`.
입력: 사용자가 제공한 「나우로 미니 구조를 본 앱에 적용하는 업데이트 명세서」 v1.0.
범위: 명세와 본 앱 코드 비교, 기존 자동 검사 및 빌드. 이번 검토에서는 제품 코드·DB·운영 설정을 변경하거나 배포하지 않았다. 미니 구현에 대한 문서의 설명은 미니 소스를 재검증한 결과로 취급하지 않는다.

## 결론

기존 React/Node 앱 위에 단계적으로 통합 가능하다. 화면·서버·저장 구조를 미니 것으로 일괄 교체하지 않는다. 우선 날짜 유지, 행사 회차와 비용의 불확실성, 저장 보호를 해결하고 공통 검색·지도·현장 안내로 확장한다. 무오류를 보장할 수 없으며 신규 요구에 맞는 회귀 검사가 필요하다.

## 현재 확인된 기반 — 재구현하지 않을 부분

- `shared/engine.ts`: 서로 다른 종류의 장소를 같은 코스로 계산, 최대 4곳 추천, 인접 구·군 포함, 시간·예산·마감 검증. 선택 장소 포함 조건과 미확인 정보 동의가 이미 있다.
- `src/App.tsx`: 장소 교체·제외·앞으로 이동 후 재계산. 체류시간 직접 편집은 추가 구현 대상이다.
- `shared/korea-time.ts`: 한국 시간 입력 변환. 전체 여행 맥락의 통합은 별도다.
- `shared/event-identity.ts`, `shared/location-quality.ts`: 중복 행사 판별·구군 정확 일치 처리. 새 모델 전환 시 기존 ID와 판별 규칙을 유지한다.
- `server/auth.mjs`, `server/store.mjs`: 인증·계정 소유권과 게스트 기록 병합 코드가 존재한다. 문서의 화면 관찰만으로 인증 서버 전체를 미구현으로 간주하면 안 된다. 현재 운영 연결·영구 저장 내구성은 별도 확인해야 한다.
- `src/RouteShare.tsx`: 복사·텍스트 다운로드·기기 공유. 공유 URL로 동일 코스 재열람하는 기능과는 다르다.
- 출처 오류/빈 목록 구분 및 카탈로그 지연 대응은 일부 이미 구현·검사되어 있다. 미니의 캐시 기간을 그대로 추가하지 않는다.

## 명세에서 조정할 내용

1. **저장함 독립 메뉴를 재추가하지 않는다.** 사용자가 ‘저장은 삭제하고 코스는 유지’로 정리한 방향을 우선해 ‘코스 > 담은 장소 / 보관한 코스’로 구성한다. 저장 기능과 독립 메뉴는 구분한다.
2. `/ko/?tab=MAP`, `ROUTES` 및 기존 TRIP→ROUTES 호환을 유지한다. 새 URL이나 v1 API 명칭은 기능상 필요할 때만 추가한다.
3. 현재 Place 모델에 선택 필드를 먼저 추가하고 변환 계층으로 Event/Occurrence를 연결한다. 기존 Point 필수값을 갑자기 null로 바꾸면 지도·거리 계산이 깨질 수 있으므로 타입·검증·사용처를 함께 변경한다. 좌표 없는 원본도 탐색 목록에는 보존한다.
4. 계정 저장과 브라우저 장소 저장은 현재 별도 경로다. 인증 코드가 있다고 장소 북마크까지 계정 동기화된 것으로 표시하지 않는다.
5. 미니의 localStorage는 도메인이 다르므로 자동 이전할 수 없다. 미니 사용자 이전은 내보내기/가져오기 또는 검증된 계정 연결의 별도 작업이다.
6. 문서에 나온 3가지 추천 전략은 현재 결과 3개와 같지 않다. 전략별 점수와 이유를 구현·검사한 뒤 표시한다.
7. 실쿠폰·결제·예약·토스 SDK를 이번 웹 통합에 끼워 넣지 않는다. 기존 회원·업체·관리자 화면과 데이터는 유지한다.

## 실행 순서 및 배포 조건

1. 기존 코스·장소 저장 예시 및 DB 백업/복구 확인, 구버전 fixture 확보.
2. 날짜 유지·선택 누락 안내·저장 실패 처리부터 독립 수정.
3. 회차·비용·출처 신뢰도 필드와 기존 데이터 변환 추가. 실제 없는 정보를 추정값으로 확정하지 않음.
4. 영문 검색·표기와 공통 목록/지도, 현장 한국어 주소 카드 구현.
5. 체류 편집·공유 링크·오프라인 읽기·계정 북마크 병합은 각각 별도 검수 후 노출.
6. 새 기능을 끌 수 있게 유지하고, 구버전 원본은 복구 검증 전에 삭제하지 않는다. QA01–18은 관련 단계별로 실제 결과 기록 후 배포.

## 이번 검증 결과와 한계

- `npm test`: 109건 통과, 실패 0. 첫 실행의 로컬 HTTP 접속 EACCES는 검사 환경 제한이었고 로컬 접속 허용 후 전체 재실행 통과.
- `npm run build`: TypeScript 검사 및 빌드 통과. 메인 JS 약504kB(압축166kB)로 번들 크기 경고가 남음. 이후 화면별 분할 대상이며 기능 실패는 아님.
- 기존 자동 검사가 새 회차 모델, 손상 저장 복구, 공유 토큰, 실제 해외 접속, 실기기 오프라인을 검증한 것은 아니다.
- 이번에 운영 인증/DB/배포 상태를 새로 조회하지 않았다. 기존 로그인 코드·테스트 통과와 실제 운영 연결 완료는 구분한다.
- 제품 코드·DB·운영 홈페이지 변경/배포 없음. 이 문서는 검토 결과이며 구현 완료 보고가 아니다.
