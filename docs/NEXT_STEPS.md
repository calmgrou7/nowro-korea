# NOWRO 출시까지 남은 작업 — 2026-10-07

## 지금 완료한 단계

- 16개 구·군 탐색과 등록 폼, 상점 제출→관리자 승인→공개 노출 흐름, 결제 증명 기반 4개 지역 스탬프와 단일 보상 선택은 로컬 시험 구현을 갖췄다.
- 서버에서 Supabase 이메일 인증번호를 검증하는 코드, 회원 기록 이관, 로그인 토큰 암호화, 장애와 실제 만료의 구분을 구현했다.
- 운영 데이터의 온라인 백업·검증·기존 파일을 덮어쓰지 않는 복구 기능을 구현했다.
- 자동 테스트 44개와 앱 빌드를 통과했다. 실제 이메일 송신과 원격 DB 연결 결과를 대신하는 검증은 아니다.

## 다음 연결 단계

1. **실제 이메일 로그인 시험.** 지정된 `rpkvpbdzemesckzizybq` 프로젝트와 제공된 publishable key를 서버에 설정했고 사용자가 메일 수신을 확인했다. 사용자가 브라우저 관리자 로그인을 완료한 뒤 Supabase Site URL의 localhost 설정을 현재 나우로 주소로 수정했다. 메일 편집의 SMTP/Pro 제한에 맞춰 기본 이메일 버튼 콜백을 구현해 공개 서버에 반영했다. 새 메일 버튼→표시된 계정 확인→로그인→다른 기기 기록 복원→로그아웃을 실제 사용자로 검증한다. 서버와 로그인 화면 준비 성공은 실제 로그인 완료를 의미하지 않는다.
2. **운영 DB·이미지 저장소 전환.** 회원/상점 소유권, 등록 이미지, 결제 증명, 보상·배송 데이터를 반영한 원격 스키마와 RLS, 서버 데이터 어댑터를 구현하고 시험한다. 기존 `supabase/schema.sql`은 초기 준비 스키마로서 최신 기능까지 모두 담은 운영 DB가 아니다. 백업 후 별도 시험 환경에서 이관하고 건수·권한·중복 보상 방지를 대조한다.
3. **상점 승인과 실제 장소 검증.** 업체 신청·소유권 확인·관리자 승인으로 권한을 부여한다. 실주소·좌표·영업시간·가격·사진 사용권을 확인한 장소만 추천 데이터로 승격한다. 지금의 샘플·AI 대표 사진을 실제 업체 검증 완료로 표시하지 않는다.
4. **고정 서버와 HTTPS 주소.** 배포 계정·요금제·도메인을 정하고 배포한다. 현재 Render 설정은 유료 영구 디스크 서버를 위한 준비이며 실제 서비스를 생성하지 않았다. 모바일, 재배포 후 데이터 유지, 백업 복구, 인증메일을 확인한다. 임시 터널은 PC와 연결 프로세스에 의존한다.
5. **실결제·현장 QR·배송·샵 연결.** 결제사 승인 또는 매장 결제 완료 검증을 서버에서 받아야 한다. 취소·환불 시 스탬프와 보상을 어떻게 처리할지 확정하고 구현한다. 굿즈 재고·국가별 배송비/제한·연락처·할인 조건·쇼핑몰 URL을 연결한다. 샘플 결제와 보상 신청 상태는 실제 결제·출고를 의미하지 않는다.
6. **추천 품질과 출시 검증.** 실제 이동시간 공급자, AI 설정, 번역 검수, 개인정보/회원 탈퇴·보존 정책, 국내외 사용자 모바일 현장 시험을 마친다. 4개 지역 완주 규칙은 사용자 확정사항이며 16개 지역 탐색 확장과 별개로 유지한다.

Supabase 지정이 끝나면 1번을 실제 연결하며, 나머지 계정 준비와 운영 정책에 의존하지 않는 코드 작업은 순서대로 진행할 수 있다.
