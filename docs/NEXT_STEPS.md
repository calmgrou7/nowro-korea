# NOWRO 출시까지 남은 작업

**2026-10-18 최신 기준:** [검수 결과와 제작 순서](REVIEW_AND_PROCESS.md)와 [고정 도메인 연결 체크리스트](DOMAIN_GO_LIVE_CHECKLIST.md)를 따른다. 사용자는 `nowro.com` 도메인 등록을 진행할 예정이며, 앱 설치·Play 등록은 기능 및 운영 검수 이후에 진행한다.

## 지금 완료한 단계

- 16개 구·군 탐색과 등록 폼, 상점 제출→관리자 승인→공개 노출 흐름, 결제 증명 기반 4개 지역 스탬프와 단일 보상 선택은 로컬 시험 구현을 갖췄다.
- 서버에서 Supabase 이메일 인증번호를 검증하는 코드, 회원 기록 이관, 로그인 토큰 암호화, 장애와 실제 만료의 구분을 구현했다.
- 운영 데이터의 온라인 백업·검증·기존 파일을 덮어쓰지 않는 복구 기능을 구현했다.
- 업체 신청→관리자 소유권 확인→전문가 권한 승인→자기 업체 상품 등록·게시·권한 회수 흐름을 구현했다. 자동 테스트 54개와 앱 빌드를 통과했고, 격리 브라우저에서 회원·관리자 화면을 확인했다. 실제 이메일 송신과 원격 DB 연결 결과를 대신하는 검증은 아니다.

## 다음 연결 단계

1. **실제 이메일 로그인 시험.** 지정된 `rpkvpbdzemesckzizybq` 프로젝트와 제공된 publishable key를 서버에 설정했고 공개 서버 상태 API가 정상 응답한다. 새 메일 버튼→계정 확인→로그인→다른 기기 기록 복원→로그아웃을 실제 사용자로 최종 검증한다.
2. **운영 DB·이미지 저장소 전환.** 회원/상점 소유권, 등록 이미지, 결제 증명, 보상·배송 데이터를 반영한 원격 스키마와 RLS, 서버 데이터 어댑터를 구현하고 시험한다. 현재 업체 신청 테이블은 SQLite에 있으며, 기존 `supabase/schema.sql`은 최신 운영 DB가 아니다.
3. **상점 승인과 실제 장소 검증.** 신청·소유권 확인·관리자 승인 흐름은 구현됐다. 운영자는 실주소·좌표·영업시간·가격·사진 사용권을 확인한 장소만 추천 데이터로 승격한다. 지금의 샘플·AI 대표 사진을 실제 업체 검증 완료로 표시하지 않는다.
4. **고정 서버와 HTTPS 주소.** `nowro.com` 등록 후 고정 호스팅 주소와 DNS를 연결한다. `PUBLIC_APP_URL`, Supabase Site URL, Redirect URL을 같은 HTTPS 대표 주소로 맞춘다. 모바일, 재배포 후 데이터 유지, 백업 복구, 인증메일을 확인한다. 임시 터널은 PC와 연결 프로세스에 의존한다.
5. **실결제·현장 QR·배송·샵 연결.** 결제사 승인 또는 매장 결제 완료 검증을 서버에서 받아야 한다. 취소·환불 시 스탬프와 보상을 어떻게 처리할지 확정하고 구현한다. 굿즈 재고·국가별 배송비/제한·연락처·할인 조건·쇼핑몰 URL을 연결한다. 샘플 결제와 보상 신청 상태는 실제 결제·출고를 의미하지 않는다.
6. **추천 품질과 출시 검증.** 실제 이동시간 공급자, AI 설정, 번역 검수, 개인정보/회원 탈퇴·보존 정책, 국내외 사용자 모바일 현장 시험을 마친다. 4개 지역 완주 규칙은 사용자 확정사항이며 16개 지역 탐색 확장과 별개로 유지한다.

Supabase 지정이 끝나면 1번을 실제 연결하며, 나머지 계정 준비와 운영 정책에 의존하지 않는 코드 작업은 순서대로 진행할 수 있다.
