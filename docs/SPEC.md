# NOWRO Korea 앱기획서 및 Codex 제작지시서

## 1. 개발 목표

NOWRO Korea의 실제 사용 가능한 MVP를 개발한다.

NOWRO는 외국인 자유여행객(FIT)의 현재 위치, 여행기간, 숙소, 남는 시간, 동행자, 예산, 취향을 바탕으로 **지금 실행할 수 있는 부산 로컬 여행코스**를 추천하는 AI Local Travel Platform이다.

브랜드와 문구는 다음으로 고정한다.

- 브랜드: NOWRO / NOWRO Korea
- 영문 슬로건: Your Korea. Right Now.
- 한국어 메시지: 지금, 진짜 한국으로.
- 핵심 방향: Search Engine → Decision Engine

첫 사용자 경험은 다음 질문에 답해야 한다.

**“지금 부산에서 2시간 남았는데, 내 조건에 맞춰 무엇을 할 수 있을까?”**

장소를 나열하는 데서 끝내지 말고, 이동·체류·영업시간·예산·숙소 복귀를 고려한 코스를 제시한다.

## 2. 개발 방식과 기본 원칙

대표가 AI 도구를 활용해 직접 개발·운영할 수 있는 구조로 만든다.

기존 저장소가 있다면 먼저 프로젝트 구조와 지침을 확인하고 현재 기술 구성을 따른다. 새 프로젝트라면 다음을 기본 구성으로 사용한다.

- 프런트엔드: React + TypeScript 기반 모바일 우선 웹앱
- 배포 형태: PWA
- 데이터·인증·파일: Supabase
- AI: OpenAI API
- 지도·경로: 선택한 지도 API와 외부 길찾기 연결
- 코드 관리: Git 기반 변경 이력
- 장소·쿠폰·스탬프 관리는 관리자 화면에서 수행

세부 라이브러리와 API 사용 방식은 구현 시 공식 문서를 확인한다. 특정 최신 버전이나 요금제를 임의로 가정하지 않는다.

기능별로 작은 단위로 구현하고, 실제 동작과 권한을 확인한 뒤 다음 단계로 진행한다.

외부 API 키가 없더라도 핵심 화면과 데이터 흐름은 개발할 수 있게 구성한다. 다만 샘플 데이터·예상 이동시간·AI 미연결 상태는 사용자와 관리자에게 명확히 구분한다. 존재하지 않는 기능이 작동하는 것처럼 표시하지 않는다.

## 3. 초기 고객과 서비스 지역

### 고객

한국어에 익숙하지 않은 외국인 FIT가 우선 고객이다.

다음 조건을 제품에 반영한다.

- 한국 전화번호 없이 이용 가능
- 추천 생성 전 회원가입 불필요
- 주소·장소명을 한국어와 선택 언어로 확인 가능
- 위치권한을 거부해도 수동 위치로 이용 가능
- 가격은 KRW 기준으로 명확하게 표시
- 여행 중 한 손으로 조작하기 쉬운 화면
- 저속 네트워크에서도 핵심 정보를 읽을 수 있는 구조

### 지역

첫 MVP는 부산의 다음 4개 권역을 지원한다.

1. 해운대
2. 광안리
3. 서면
4. 영도

부산 전역 → 경남 → 전국으로 확장할 수 있도록 도시와 권역을 데이터로 관리한다. 코드에 부산 장소나 권역을 직접 고정하지 않는다.

### 언어

KR / EN / JP / 중문 간체 / 중문 번체를 지원한다.

첫 방문 시 브라우저 언어를 참고하고 사용자가 언제든 변경할 수 있게 한다. 기본 영문 화면을 준비하며, 번역 누락 시 빈 문구나 내부 번역 키를 노출하지 않는다.

## 5. 전체 화면 구조

여행자용 하단 메뉴는 다음 5개로 구성한다.

| 메뉴 | 목적 |
|---|---|
| NOW | 현재 상황에 맞는 추천 시작 |
| MAP | 주변 장소·쿠폰 탐색 |
| TRIP | 생성·저장한 코스 확인 |
| PASS | 보유 쿠폰과 사용 조건 확인 |
| PASSPORT | 방문 스탬프와 지역 미션 확인 |

언어·여행정보·동의·계정 관리는 상단의 프로필 또는 설정에서 제공한다.

사업자와 운영자 화면은 여행자 화면과 구분한다.

## 6. 여행자 핵심 이용 흐름

**첫 방문 → 언어 선택 → 위치 설정 → 시간·취향 입력 → 코스 비교 → 장소 확인 → 길찾기 → 쿠폰 사용 → 방문 기록**

추천 생성 전에는 가입을 요구하지 않는다.

코스·쿠폰·스탬프를 계정에 저장할 때 간단한 가입을 제공한다. 비회원 이용정보를 계정으로 옮기는 방법과 만료 기준을 설계한다.

여행 시작일과 종료일, 숙소는 저장할 수 있지만 즉시 추천에 모두 필수로 요구하지 않는다. 필요한 정보부터 단계적으로 입력받는다.

## 7. NOW: 여행조건 입력

다음 정보를 입력받는다.

| 항목 | 입력 방식 |
|---|---|
| 현재 위치 | GPS / 장소 검색 / 권역 선택 |
| 여행지역 | 도시·권역 |
| 여행기간 | 시작일·종료일, 선택 입력 |
| 숙소 위치 | 장소 검색, 선택 입력 |
| 남는 시간 | 2시간 / 4시간 / 반나절 / 하루 |
| 동행자 | 혼자 / 커플 / 친구 / 가족 |
| 이동수단 | 도보 / 대중교통 / 차량 |
| 예산 | 기본적으로 1인 기준 KRW |
| 취향 | 바다·음식·카페·문화·체험·쇼핑·웰니스 |
| 추가 조건 | 어린이 동반·접근성·식이조건 등 |
| 복귀 조건 | 숙소 또는 지정 장소, 마감시간 |

반나절과 하루는 각각 기본 시간값을 제공하되 사용자가 변경할 수 있게 한다.

예산에는 포함·제외 범위를 표시한다. 차량 이용 시 주차·통행료 등 확인하지 못한 비용을 숨기지 않는다.

자연어 입력도 제공한다.

예시: “광안리에서 4시간, 바다와 카페, 1인 6만원 이내.”

자연어에서 추출한 조건은 사용자에게 보여 주고 수정할 수 있게 한다.

## 8. 여행코스 추천 규칙

AI가 임의의 장소·영업시간·가격을 만들어 내지 못하게 한다.

추천은 다음 순서로 처리한다.

1. 사용자 조건을 구조화한다.
2. 등록된 장소에서 위치·취향 후보를 찾는다.
3. 영업·최종 입장·예약·동행자 조건을 검사한다.
4. 이동시간·체류시간·복귀시간·완충시간을 계산한다.
5. 시간과 예산에 맞는 코스를 구성한다.
6. AI가 추천 이유와 다국어 설명을 작성한다.
7. 최종 장소ID·시간·비용을 다시 검증한다.

핵심 조건은 다음과 같다.

**총 이동시간 + 체류시간 + 대기시간 + 복귀시간 + 완충시간 ≤ 사용 가능한 시간**

영업시간과 최종 입장시간은 장소 도착 시점에 맞춰 검사한다.

지도 경로정보가 없는 경우 직선거리를 정확한 이동시간처럼 표시하지 않는다. 추정임을 명시하고 보수적인 완충시간을 적용하거나 추천 범위를 줄인다.

조건에 맞는 코스가 없으면 장소를 억지로 채우지 않는다. 시간을 늘리거나 예산·이동수단·권역을 변경하는 선택지를 제시한다.

## 9. 추천 결과와 TRIP 화면

최대 3개의 코스를 비교할 수 있게 한다.

각 코스에는 다음을 표시한다.

- 코스명과 추천 이유
- 총 소요시간
- 예상 1인 비용과 비용 범위
- 장소 수와 이동수단
- 시작·종료·복귀 예상시간
- 장소별 도착·체류·출발시간
- 쿠폰 적용 여부
- 예약 필요 여부
- 정보 출처와 확인시점
- 미확인 정보와 이용 주의사항

장소 교체, 제외, 순서 변경 기능을 제공한다. 변경 후에는 전체 시간·영업·비용을 다시 검사한다.

여행 중 “시간이 줄었어요”, “다른 장소로 바꿔 주세요”를 누르면 현재 위치와 남은 시간을 기준으로 재추천한다.

사용자가 원래 입력한 숙소·복귀 조건은 재추천에서도 유지한다.

## 10. MAP과 장소 상세

### MAP

- 장소·쿠폰·코스 경유지 표시
- 관광·음식·카페·체험·쇼핑·웰니스·지역서비스 필터
- 목록과 지도 전환
- 현재 위치 또는 수동 기준점 표시
- 지도 로딩 실패 시 목록으로 이용 가능

“영업 중”은 충분한 운영시간 데이터가 있을 때만 사용한다.

### 장소 상세

- 선택 언어 장소명과 한국어 장소명
- 사진과 이용권리 정보
- 한국어 주소·주소 복사
- 영업일·휴무·최종 입장시간
- 가격범위·예상 체류시간
- 예약 필요 여부
- 외국어 이용·결제·접근성 조건
- 업체 확인된 식이·동반자 조건
- 쿠폰·스탬프 참여 여부
- 공식 홈페이지·전화·외부 예약 링크
- 출처·최근 확인일
- 길찾기·코스 추가·오류 신고

식이·접근성 정보는 확인된 사실만 표시한다. AI 추정으로 인증이나 안전을 보장하지 않는다.

## 11. NOWRO Pass

초기 Pass는 **무료 로컬 쿠폰 월렛**이다.

쿠폰에는 다음 정보를 포함한다.

- 제공 업체
- 혜택과 적용 대상
- 사용기간
- 최소 결제금액
- 제외 상품·요일·시간
- 1인당 사용 횟수
- 발급·사용 수량 상한
- 중복 할인 가능 여부
- 현장 사용방법

쿠폰 상태는 발급 가능 / 보유 / 사용 완료 / 만료 / 취소로 구분한다.

사용자가 버튼을 누르는 것만으로 사용 완료가 되지 않게 한다. 사업자의 확인 또는 적절한 현장 인증을 거쳐 사용을 확정한다.

동일 쿠폰의 중복 사용과 사용 수량 초과를 서버에서 차단한다.

## 12. NOWRO Passport

전자스탬프는 지역 방문 기록과 다음 경험 추천에 사용한다.

GPS 근접 확인과 현장 QR을 활용하되, GPS만으로 실제 방문·구매를 확정하지 않는다.

- QR 검증은 서버에서 수행
- QR에 만료·서명·중복방지 적용
- 같은 장소의 중복 획득 기준 명시
- GPS 오차·권한 거부 시 대체 인증 지원
- 보상·미션은 운영자가 생성·중지 가능
- 위치이력 전체를 저장하지 않고 필요한 기록으로 최소화

스탬프 기록과 쿠폰 사용완료, 예약완료는 서로 다른 이벤트로 관리한다.

## 13. NOWRO Partner와 관리자

### Partner

사업자는 본인 업체에 대해서만 다음을 관리한다.

- 장소정보 수정 요청
- 사진·가격·영업시간 관리
- 쿠폰 생성·중지
- 현장 쿠폰 사용 확인
- 스탬프 참여 설정
- 집계된 노출·코스 포함·쿠폰 사용 확인

사업자에게 여행자의 숙소·개인 동선·연락처를 제공하지 않는다.

### 운영자

- 도시·권역·카테고리 관리
- 장소·번역·사진 승인
- 업체 계정과 소유권 검증
- 쿠폰·미션 검수
- 데이터 갱신·오류 신고 처리
- 광고 표시와 추천 정책 관리
- 이용·AI 비용·오류 모니터링
- 승인·수정·사용취소 감사기록

사업자가 수정한 핵심 정보는 승인 상태와 실제 공개 상태를 구분한다.

## 14. 데이터 구조

| 영역 | 주요 데이터 |

| 장소 번역 | 언어별 이름·설명·이용조건 |
| 운영시간 | 요일, 휴무, 예외일, 최종 입장 |
| 여행 | 조건, 기간, 복귀점, 저장 상태 |
| 코스·경유지 | 장소ID, 순서, 시간, 비용, 계산 근거 |
| 업체 | 사업자 상태, 승인, 담당 계정 |
| 쿠폰·발급·사용 | 조건, 수량, 사용자, 상태, 사용 증빙 |
| 스탬프·미션 | 장소, 인증, 참여, 보상 상태 |
| 동의 | 동의 종류, 버전, 시점, 철회 |
| 이벤트·감사 | 이용 퍼널, 권한 작업, 변경 기록 |

가격·영업정보·번역마다 확인 근거와 갱신시점을 추적할 수 있게 한다.

사진에는 출처와 이용권리를 기록한다. 지도·OTA 데이터를 허용 범위 밖으로 복제하지 않는다.

## 15. AI와 보안

OpenAI API는 자연어 조건 추출과 추천 설명에 사용한다. 거리·비용·영업 제약은 코드와 데이터로 검증한다.

- AI 응답은 구조화된 형식으로 받고 검증
- 등록되지 않은 장소ID는 거부
- 예약재고·혼잡을 확인하지 못하면 미확인 표시
- AI 장애 시 검증된 규칙형 코스 또는 재시도 안내
- API 호출 상한·시간제한·비용 로그 적용
- 비밀키는 서버에서만 사용
- 이름·정확한 숙소·위치이력을 AI에 불필요하게 전송하지 않음

Supabase의 공개 데이터 접근에는 RLS와 소유권 검사를 적용한다.

사용자 A가 사용자 B의 여행·쿠폰·스탬프에 접근하거나, 사업자 A가 사업자 B의 정보를 수정할 수 없어야 한다.

위치동의와 개인정보 처리방침을 준비하고, 국외 이전·보존기간·신고 적용은 실제 운영구조에 맞춰 출시 전에 확인한다.

## 16. 디자인 지침

글로벌 Travel Tech 스타일로 디자인한다.

- Deep Charcoal: 주요 텍스트·브랜드 영역
- Lime: 추천 시작·주요 행동·활성 상태
- White: 기본 배경
- Ocean Blue: 지도·정보·보조 강조

화면은 모바일 우선으로 설계하되 태블릿·데스크톱에서도 사용 가능해야 한다.

핵심 행동은 화면마다 하나를 가장 명확하게 보여 준다. 장소 목록은 짧게 읽을 수 있게 하고, 조건·가격·시간은 설명문보다 쉽게 비교할 수 있도록 구성한다.

색만으로 상태를 구분하지 않는다. 터치 영역·텍스트 대비·키보드 조작·스크린리더 이름을 확인한다.

사진과 UI에서 특정 국적·연령·성별만을 대표 여행자로 고정하지 않는다.

## 17. 개발 순서

### 1단계: 프로젝트와 화면
기존 코드 확인, 실행환경, 모바일 레이아웃, 다국어, NOW 입력, 장소 목록·상세.

### 2단계: 데이터와 권한
Supabase 데이터 구조, 장소관리, 여행 저장, 사용자·업체 소유권, 관리자 승인.

### 3단계: 코스 엔진
위치 후보검색, 영업·시간·비용 검사, 시간 모드, 추천 결과, 교체·재계산.

### 4단계: AI
자연어 조건 추출, 구조화 응답, 다국어 설명, 출력 검증, 비용·장애 처리.

### 5단계: 쿠폰과 스탬프
발급·현장 사용·중복차단, QR 인증, Passport, Partner 관리.

### 6단계: 실증 준비
실제 장소 검증, 번역 검수, 오류 신고, 이벤트 측정, PWA, 배포와 운영문서.

각 단계에서 작동하는 결과를 남기고 검증한다.

## 18. 완료 기준

다음 조건을 충족해야 MVP 완료로 판단한다.

1. 비회원 외국인 사용자가 한국 전화번호 없이 코스를 생성할 수 있다.
2. GPS 거부·오류 시 수동 위치로 계속 이용할 수 있다.
3. 4개 시간 모드가 이동·체류·복귀·예산 제약을 검사한다.
4. AI가 등록되지 않은 장소나 확인하지 않은 이용정보를 확정적으로 제시하지 않는다.
5. 장소 교체 후 전체 코스를 재계산한다.
6. 지도·AI 장애가 나도 입력정보가 사라지거나 화면이 멈추지 않는다.
7. 쿠폰과 QR의 중복·권한·수량 검사가 서버에서 동작한다.
8. 여행자·업체 간 데이터 접근이 차단된다.
9. 5개 언어에서 핵심 흐름이 완료되고 중요한 이용조건이 검수된다.
10. 샘플 데이터와 실제 검증 데이터가 명확히 구분된다.
11. 모바일 화면·오류·빈 결과·로딩 상태를 확인한다.
12. 배포 방법, 환경변수 항목, 데이터 관리, 알려진 제한을 문서로 남긴다.

실증 목표는 외국인 300명·업체 30개이며, 이는 개발 완료나 확보된 성과로 표현하지 않는다.

## 19. Codex 작업 지시

이 문서를 기준으로 NOWRO Korea MVP 개발을 시작하라.

먼저 저장소와 적용 지침을 확인한 뒤, 현재 구현 상태·필요한 외부 연결·개발 순서를 정리하고 바로 실행 가능한 작업부터 진행하라.

기존 기능과 사용자의 변경사항을 보존한다. 복잡한 기능을 한 번에 만들기보다 핵심 여행자 흐름을 먼저 완성한다.

외부 계정이나 API 키가 필요한 경우 필요한 항목과 사용 목적을 명시하고, 키가 없어도 진행 가능한 화면·데이터·검증 작업을 계속한다. 비밀키를 채팅이나 프런트엔드에 노출하지 않는다.

추천·쿠폰·권한·QR 검증은 실제 동작을 확인한다. 완료 보고에는 다음을 포함하라.

- 구현된 기능
- 실행·확인 방법
- 수행한 검증과 결과
- 실제 연결된 API와 샘플로 남은 영역
- 배포 상태
- 출시 전 필요한 데이터·법률·언어 확인
- 다음 개발 단계

최종 목표는 예쁜 데모가 아니라, **외국인 여행자가 현재 조건을 입력하고 실행 가능한 부산 코스를 선택해 현장에서 이용할 수 있는 MVP**다.
