# 상점·전문가 상품 등록과 로그인 연동

## 현재 구현

- 홈 하단 `Shop & creator mode / 상점·전문가 모드`로 진입. 현재 localhost에서만 테스트 상점 계정 전환 가능. 실제 로그인은 연결되지 않았음.
- 등록 유형: 상점·상품, 서비스, 체험, 관광지, 콘텐츠·행사.
- 기본 정보: 지역·카테고리·운영자, 한국어/영어 제목·한 줄 소개.
- 상세: 한국어/영어 설명, 사진 최대 3장(JPG/PNG/WebP, 각 1MB), 이미지 게시 권리 확인.
- 이용 정보: 가격 범위(KRW), 이용시간, 주소/집합 장소, 공개 문의 연락처, HTTPS 예약/공식 URL, 운영·예약 안내, 포함/불포함, 취소·환불 정책, 홍보 문구.
- 임시저장과 승인 요청을 SQLite 서버 DB에 저장. 브라우저 새로고침 후 등록 관리에서 다시 수정 가능.
- 상세 미리보기, 등록 관리, 관리자 승인/수정 요청 및 심사 의견.
- 승인된 등록은 메인 홍보 영역(최신 4개)과 탐색에 표시. 카드에서 상세페이지를 열고 상세 링크 복사 가능. `?listing=등록ID`로 공개 상세 직접 접근.
- 보관·노출 중지는 복구 가능한 archived 상태. 수정하여 다시 게시 요청 가능.
- 등록 UI와 본문은 한국어/영어 지원. 일본어·중국어 선택 시 신규 등록 기능의 안내와 본문은 영어로 표시. 자동 번역은 제공하지 않음.

## 게시 흐름

`draft → pending → published / rejected`

상점 제출만으로 공개하지 않으며 관리자 승인 후 노출. 게시 중인 내용을 저장·수정하면 draft/pending으로 돌아가고 재승인 전까지 노출 중단. 보관 시 archived. 심사 승인은 게시 허가이며 실제 영업시간·재고의 실시간 검증을 의미하지 않음.

공개 카드·상세에 업체 제공 정보임을 안내. 등록 상품은 기존 여행 코스 추천 데이터와 분리되어 있다. 실제 장소 매핑·이동 좌표·재고/예약 검증 전에는 추천 엔진에 자동 편입하지 않는다. 홍보 문구는 표시만 하며 할인·결제·예약 확정을 수행하지 않는다.

## API / 저장 구조

| API                                 | 권한             | 기능                                      |
| ----------------------------------- | ---------------- | ----------------------------------------- |
| GET /api/listings                   | 방문자           | 게시 중인 내용만 반환, 내부 owner_id 제외 |
| GET /api/operator/listings          | 상점/관리자      | 상점은 본인 등록, 관리자는 전체 등록      |
| POST /api/operator/listings/save    | 상점/관리자      | 초안/승인 요청 저장, 서버 소유권 검사     |
| POST /api/operator/listings/review  | 관리자           | pending만 승인/수정 요청                  |
| POST /api/operator/listings/archive | 소유 상점/관리자 | 보관 및 공개 노출 중지                    |

`listings`: id, owner_id(users FK), data(JSON), status, created, updated, review_note. 사용자 ID·게시 상태는 클라이언트가 임의로 지정할 수 없음. 기존 세션·CSRF·호출 제한을 적용. 서버는 필수 번역/사진 권리/가격/유형/지역/HTTPS URL/사진 MIME·시그니처·크기를 검증한다. 사진은 초기 로컬 MVP에서 data URL로 저장하므로 대규모 운영 전 별도 이미지 저장소와 썸네일로 옮긴다.

## 실제 로그인 서버 연결 시 남은 작업

1. 사용할 인증 서버 URL·세션/토큰 검증 방식·콜백 주소를 확정한다. 현재 외부 인증 정보가 설정되지 않아 연결을 완료했다고 표시하지 않는다.
2. 서버에서 인증된 사용자 ID를 내부 users.id에 안정적으로 매핑한다. 등록 owner_id는 현재 세션의 user_id를 사용하므로 폼과 게시 API의 소유권 구조를 유지할 수 있다.
3. 업체 등록/소유권 확인 절차를 거친 사용자에게 서버에서 partner 역할을 부여한다. 프론트 입력으로 역할을 부여하지 않는다. admin 역할도 서버에서만 관리한다.
4. 공개 배포에서 ENABLE_LOCAL_OPERATOR_PREVIEW=false 유지. 실제 상점 모드 진입을 로그인 후 권한 확인으로 교체. 서버 세션 상태로 UI를 선택한다.
5. 로그인/로그아웃, 세션 만료, 서로 다른 업체 계정의 읽기/수정 차단, 관리자 승인, 공개 노출, 이미지 저장소 소유권을 통합 검증한다.
6. 실제 DB가 로컬 SQLite와 다르면 listings와 audit 데이터를 이전하고 같은 권한·게시 규칙을 재검증한다. 외부 DB의 보안 정책이나 스토리지 연결은 이번 작업에서 수행하지 않았다.

외부 인증 서버나 키가 제공되기 전에는 위 최종 연결 단계가 남아 있다.

## 검증

- draft → pending → 관리자 published → 공개 API 반환 및 수정 재심사.
- 일반 사용자 등록 차단, 타 업체 읽기·수정·보관 차단, 상점 자기 승인 차단.
- 필수 영어 내용·사진/권리 확인, 잘못된 가격·URL·사진 차단.
- HTTP 세션·CSRF·400 검증 응답·공개 응답의 owner_id 미노출.
- 상점 등록 폼과 상세 미리보기 브라우저 확인. 테스트 게시 데이터는 인메모리 DB에서만 사용.
